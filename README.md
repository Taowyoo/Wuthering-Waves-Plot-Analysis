## 核心认识

1. 三个版本逐层揭开同一座城市的问题：3.5 是残响被操纵与机傀攻城；3.6 是木禺借历史数据制造的“完美”牢笼；3.7 则追问城的原始使命完成后，真实居民的生活有没有继续存在的资格。[S35B](资料索引.md#S35B)、[S36A](资料索引.md#S36A)、[S37A](资料索引.md#S37A)
2. 秧秧、清宵与心的变化可以读作同一条主题线：守护不要求成为无所不能的英雄，也不要求抹掉自己的情感。这个主题判断是分析推论，不是三人的身份等同。[S35B](资料索引.md#S35B)、[S36A](资料索引.md#S36A)、[S37A](资料索引.md#S37A)
3. 心既有源自心月狐的记忆，又拥有分离后的独立经历与选择；“恢复底层模型”与“旧岁主完整复活”不能混用。[S37A](资料索引.md#S37A)、[C37H](资料索引.md#C37H)
4. 玄翎雀、梁鸢、书信、命灯和剑意共同承担传递记忆与情感的功能。机关能保存频率，并不因此天然尊重被保存者。[S35A](资料索引.md#S35A)、[S36A](资料索引.md#S36A)、[G14](资料索引.md#G14)–[G18](资料索引.md#G18)、[C37H](资料索引.md#C37H)
5. 3.7 已解释许多建城往事，但稷字讯息、祀声之人、谛天鉴更高层的目的，以及奇谭涉及的过往，仍需保留问题。[S35M](资料索引.md#S35M)、[S37A](资料索引.md#S37A)、缺项 [D01](资料索引.md#D01) 等

## 使用与更新规则

- 文本事实、角色说法、分析推论、未解问题分别标识。角色的自责、猜测和宣传口号不自动成为客观结论。
- 库街区是转录资料；本次“已读”仅指已阅读页面可见内容，不代表官方逐句认证或实机校验通过。
- 以转述为主。证据位置采用页面小标题、发言者和场景上下文，避免依赖会变化的网页行号。
- 录像仅作为候选核验来源登记。未实际观看并定位的部分没有填写时间戳，也不用于补造剧情。
- 本次不使用玩家评论、泄露资料或纯攻略推测作为剧情事实。
- 后续优先补奇谭、危行和锁暝故事，再补活动、NPC、场景文献、声骸与对白分支。更新须同时修订报告、索引和覆盖表。

## 网站构建与发布

本仓库同时提供由三份 Markdown 原稿生成的静态网站。需要 Node.js 22；首次使用先执行 `npm ci`，然后：

```bash
npm run build    # 生成 dist/
npm run check    # 检查站内链接、208 个显式锚点和搜索样例
npm run preview  # 在 http://localhost:4173/ 本地预览
```

页面全部使用相对链接，因此既可部署在域名根目录，也可部署到 `/Wuthering-Waves-Plot-Analysis/` 项目前缀。推送到 `master` 后，GitHub Actions 会构建、检查并发布 Pages；拉取请求只运行构建与检查。仓库首次启用时，仍需由维护者在 **Settings → Pages → Build and deployment → Source** 中选择 **GitHub Actions**。
